# Deploy Shielded on Dokploy

Create a Dokploy **Application** from this repository and its `main` branch. Choose the Dockerfile build type and set its Dockerfile path to `Dockerfile.dokploy`. This image builds the testnet proof artifacts and pinned Arkade VM, then starts the first-run installer.

Add the variables from [`dokploy.env.example`](../dokploy.env.example) in the application's runtime environment. Only Mutinynet is supported. The defaults shown are the public Arkade operator and emulator URLs. `SHIELDED_ALLOW_DEV_SETUP=true` explicitly enables this repository's development-only Groth16 setup; it is suitable for Mutinynet testing, not production funds. An optional bootstrap mnemonic must be entered as a Dokploy secret, never as a Docker build argument. If omitted, the service creates and encrypts its own funding wallet and displays the public address to fund.

Use a single-node Dokploy host for this setup. In **Advanced → Volumes/Mounts**, add one persistent Dokploy volume mounted at `/data`, then set the application container port to `8792`. A default named volume is local to that host; a multi-node Swarm needs a placement constraint keeping the application on the volume’s node. Keep one replica: the SQLite journal and pool require a single active writer. The default Swarm update order works: a replacement container reports healthy and waits until the previous container releases the data volume before opening it. Keep this volume across image updates; it stores the encrypted wallet, immutable pool profile, and transaction journal. Replacing or losing it loses the operator's recoverable state. A first deploy needs funded Arkade VTXOs before it can create genesis; service startup will show the generated funding address and wait for bootstrap funding.

For the public domain, add an A record pointing your chosen hostname to the Dokploy server IP. In the application's **Domains** settings, add that hostname, route it to container port `8792` over HTTP, and enable HTTPS/Let's Encrypt. The wallet is available at `https://HOSTNAME/stock-wallet`; `https://HOSTNAME/health` is the health check. Do not expose port `8792` directly from the server firewall; Dokploy's proxy handles public traffic.

Enable deployment on pushes to `main` after the first deployment succeeds. A normal push-triggered Dokploy deployment does not wait for GitHub Actions checks. The image's bundled emulator harness performs local synthetic qualification only. Live transactions use the configured public Mutinynet emulator and operator endpoints; no custom emulator deployment or operator patch is required.

This is a bounded Mutinynet test deployment using development-only circuit-specific Groth16 phase 2. It does not provide independent pool exits during Arkade outages, and a missing offchain proof sidecar can block note recovery. Do not use mainnet funds.

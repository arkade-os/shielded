# Registered Shielded verifier service

This standalone service uses the patched emulator package generated by
`node tools/native-registry/apply.mjs`. It is a separate binary and endpoint;
it does not modify an existing emulator or its verifier profile. The signer
must be a key already accepted by the intended Arkade deployment. A Shielded
operator cannot make a new signer acceptable by deploying this service alone.

The service has two endpoints:

* `GET /v1/info` returns `version: "shielded-registry/1"`, the exact compressed `signerPubkey`,
  `registryProtocol`, `registryHash`, sorted `registeredPrograms`, and
  `maxSidecarBytes`.
* `POST /v1/tx` accepts JSON fields `arkTx`, `checkpointTxs`, and
  `registrySidecar`. Each is canonical padded base64. The response matches the
  Arkade emulator shape: `signedArkTx` and `signedCheckpointTxs`.

The registry file is an object mapping each lowercase SHA256 program ID to the
lowercase hex bytecode. Its advertised hash is SHA256 of UTF-8 compact JSON for
that map with keys sorted in ascending ASCII order. The JSON encoder emits no
whitespace and hex values need no escaping. For example, the canonical bytes
are `{"<sorted-id>":"<lowercase-program-hex>"}`. Registry configuration is
loaded once at process startup; requests cannot supply or modify programs.
The emulator VM independently validates each bytecode hash and registered
program constraints.

`POST /v1/tx` obtains every previous Ark transaction from the configured HTTPS
Arkade indexer using `/v1/indexer/virtualTx/{comma-separated-txids}`. It strips
all submitted `PrevArkTxField` values and inserts only transactions returned
for the checkpoint inputs' exact previous outpoints. Missing, duplicate,
malformed, or mismatched transactions fail closed. Checkpoint witness outputs
are reconciled against indexed transaction outputs before the upstream
emulator validates the checkpoint and executes the VM. The Arkade operator
still decides whether a signed spend is accepted and unspent.

## Build

Use Go 1.26.6 or newer and Node 24:

```powershell
node tools/native-registry/apply.mjs
Push-Location tools/registry-server
go mod tidy
go build -trimpath -o ../../bin/shielded-registry-server.exe .
Pop-Location
```

`Dockerfile.registry-server` builds the same binary in a separate container.
The image has no embedded key, registry, token, or demo signing fixture.

## Configuration and operation

The signer key file is mounted read-only and contains one lowercase 32-byte
hex scalar. The service rejects the public demo fixture scalars. Configure the
Ark operator signer as canonical compressed hex and set the trusted indexer to
an HTTPS origin (for example, `https://mutinynet.arkade.sh`). Keep the registry
file immutable and mount it read-only. The reported signer key must match the
key already registered by Arkade for the deployed covenants.

The default listener is loopback at `127.0.0.1:8790`. A non-loopback listener
requires a mounted bearer-token file with at least 32 bytes. Put public traffic
behind a TLS reverse proxy with request rate limits, body limits, and access
logging that excludes authorization headers and request bodies. This endpoint
returns emulator approval signatures only. It does not perform Ark operator
finalization, preconfirm a spend, admit it to Arkade, or submit a transaction.
Those actions require the actual Arkade operator path.

Required flags:

```text
--registry /etc/shielded/registry.json
--emulator-key-file /run/secrets/emulator-key
--ark-signer <compressed Ark operator public key>
--indexer-url https://mutinynet.arkade.sh
--api-token-file /run/secrets/registry-api-token   # required off loopback
```

The four-input and 128 KiB sidecar limits match the experimental Shielded
registered-program profile. These limits do not establish production capacity.
The service runs at most two verifier calls concurrently and returns HTTP 429
when both slots are occupied. Arkade's default compute budget still applies;
the VM API does not provide a cancellable wall-clock deadline, so this bounded
deployment kit is not a claim of resistance to public denial-of-service.
